# Primary-source search and the decisions it changes

Source hashes, repository commit IDs and retrieval times: [primary-source-reads.json](primary-source-reads.json). These are algorithm references, not experimental results for the competition candidate.

- [libdeflate deflate_compress.c, 92e6a0d](https://github.com/ebiggers/libdeflate/blob/92e6a0db9fa848d742f9eb286c92afc60f2c3dda/lib/deflate_compress.c): `deflate_choose_default_litlen_costs` estimates a match/literal mixture using greedy match frequencies and a minimum-match-length heuristic. `deflate_set_initial_costs` chooses default costs or mixes them with previous-block costs. `deflate_optimize_and_flush_block` refines costs and tracks actual encoded cost. This supports trying inexpensive initial statistics, while exposing short-match bias as a follow-up question if the new seed loses size. It does not establish our sparse seed's quality. A wholesale transplant would also change block boundaries and incur substantial proof work, so it is not the first experiment.
- [Zopfli squeeze.c, df1517d](https://github.com/google/zopfli/blob/df1517dd8518113a245e4d203a04b8a0e02ab493/src/zopfli/squeeze.c): `ZopfliLZ77Optimal` obtains initial statistics from a greedy parse, then repeats shortest-path optimization and evaluates actual block size. This is independent implementation precedent for separating seed statistics from the expensive planning step. Its many iterations and randomization are not transplanted into the balanced candidate: earlier project measurements show that added passes have a poor time/size tradeoff. The next experiment must first establish the quality of one or two passes after the forward stage is removed.

## Combinable range-minimum experiment

The local source shows that `d_best_len` scans disjoint candidate-length intervals, so there is no duplicate full-range work to remove. A distinct possibility is to cache minima across finalized groups of eight future endpoints. Inside an actual constant-price run, one group minimum replaces eight endpoint reads; scalar edges retain the original shortest-length tie order. Summaries are built only after all eight positions are finalized. A 1024-cell ring separates at-most-255 backward pushes from the at-most-258 future query window.

This is a hypothesis about reducing repeated reads across different positions, not a claim that backward work alone can reach the frontier. New source is `candidates/r10-rmq8`, generated by `scripts/build-round10-rmq.py`. Minimal discrimination: independent model check, exact finite token/output comparison, then paired official total time. Stop on any unexplained output mismatch or no repeatable total-time benefit; only combine with a promising forward candidate after measuring the actual combination. The copied parent Lean file is explicitly unadapted.
