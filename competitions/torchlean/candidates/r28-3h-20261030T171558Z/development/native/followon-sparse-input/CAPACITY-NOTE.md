# 逻辑长度不等于分配体积

压缩到一个packet只是去掉单独index/tuple的需求。若producer仍以原k做`Array.mkEmpty k`，即使只push约k/2非零项，容量仍可保留k，不能把逻辑长度减半写成分配字节减半。

从空容量增长会多次分配/复制；先统计非零数再精确分配会多一遍扫描。两者都必须和一次准备、保留k容量的版本在完整边界比较，不能假定“更稀疏”必然省时。packet是立即数只减少单值对象需求，不免除array header、增长或析构检查。

可分别记录实际capacity/分配、写入数、后续读取working set及析构size；这些量支持成本解释，不代替整模型配对时间。当前没有Native实现/测量，所有收益UNKNOWN，不增加本轮候选或CI。
