## 已由源码及有限模型核实

**前向和后向不能混用。** 本次对象是 `d_parse` 的前向统计种子；`d_plan_k:2274–2287` 再据此拟合成本并调用后向 `d_dp`。后向 `d_best_len:1638–1647` 确实逐长度枚举，其既有 RMQ／span 结果不能充当前向事件的新证据。

1. `D_KNOBS:85` 的 `flen` 只有 8／16。`d_fill_nextl:1911–1925` 对 `l < flen` 用 `l+1`，之后跳到包含 `l+1` 的长度码域终点。`relax_run:991–1017` 写入从 `lo` 出发的 `nextl` 轨道，最后另写 `hi`，不是整个 `[lo,hi]`。
2. 对本次两个 `flen` 和 `3 ≤ lo,hi ≤ 258`，精确采样集合为：`lo、hi`，加 `[lo,min(hi,flen)]`，加严格大于 `max(lo,flen)` 且小于 `hi` 的全局码域终点；`hi < lo` 为空。共 **131,072** 个有序边界对逐一核对通过。`3..258` 仅 29／32 个写点，每个 `flen` 以上的单一码域最多 2 个写点。例：`lo=19, hi=22, flen=16` 只写 19 和 22；全区间事件新增 20、21，模型中立即改变 ring 值。`lo=19,hi=21` 两端又都不是全局码域终点，不能只保留终点表。
3. `d_relax_cands:2065–2078` 和 `relax_cands:1198–1216` 以 `lo=3` 起步，每个候选后设 `lo=len+1`。一个更远候选只获得其新增长度段，不能让每个距离都覆盖 `3..len`。逆向扩展为单独的受限边：`fback<100` 只发最优扩展的全长；`fback≥100` 还经原 `relax_cands` 对所选起点发采样截短边。
4. `d_record:2201` 发生在 skip 判断之前；`best≥skip` 的 `2216–2238` 直接回溯、发最长匹配并重开 chunk，不调用 `d_relax`。未搜索续接分支 `2163–2166` 只发一个全长 `relax_one`。记录中的长匹配数量不能代表待替换的 `relax_run` 写数；29／32 是 helper 示例，不是实际公共调用分布。
5. `relax_run:1003–1015`、`relax_one:1175–1178` 比较完整无符号 `u64`：高 32 位是 **u32 回绕后的成本**，低位是 `(distance<<9)|length`。同成本时 literal 的 choice=0 优先，其后距离较小优先，再长度较短优先。在同一目标位置、同距离下，长度较短等于起点较晚；按先到或只按成本取值会丢失重构规则。5,000 个包含回绕、不同旧值与 8192 ring 跨界的随机 helper 差分通过。
6. `back_best:1147–1159`／`d_back_best:2033–2045` 先按 `pa[i-t].cost + lc[len+t]` 的回绕小计选 `t`，初值 `INF`，只接受严格更小值，平局保留较小 `t`；选完才加距离成本。一般 u32 输入下，不能把距离成本提前加入并假定排序不变，亦不能把初值当成无穷大。若优化依赖实际成本不回绕／小于 INF，需要单独证明可达状态界。

**INFERRED 的可达状态界，未形式化：** D 固定 `huff=0:2112`，`costs_from:725` 将符号价限制为 8..320，结合 `LEXTRA/DEXTRA:125–135` 可得 literal≤320、length≤400、distance≤528。若逐步保留当前 chunk 的 literal 可达性及 `i-s≤4096`，直接／向后扩展到达成本的保守界为 `320*4096+400+528=1,311,648 < INF`；skip 重开 chunk，扩展不越过 s。这个短归纳可用于专门 D 变换的无回绕桥梁，不能外推到任意 helper 参数。Python 只核对该界的常数和算术，没有证明可达性；通用回绕反例不意味着真实 D 会溢出。

## 事件形式的实际余地

对完整码域 `[a,b]`，全长度算法本可在目标 `q` 上对多个源 `i∈[q-b,q-a]` 取滑动最小；**原采样只保留码域终点 `b`，此时该部分只对应 `i=q-b` 一个源**。额外 `lo/hi` 也是候选专属点。维持同一集合的事件可正确表示为点消息或稀疏掩码，但仍需触达这些点，维护堆／队列／过期信息不自动减少工作。当前 `pa[(i+l)%8192] = min(old,v)` 已在用固定到达槽立即归约所有竞争者。

短长度前缀确有密集写入，但其上限只有 8／16，而且单一码域宽度很小；这不是原提案所需的长区间。把稀疏集合包成完整区间后再过滤，或者扩边来得到滑窗结构，分别增加检查或改变行为，都没有本次可据以投入完整实现的信号。

**真实计数待路线 B 提供，当前为 UNKNOWN：** 实际 sampled 写数、每次调用跨度、成功降低 ring 的比例、动态换价／chunk reset 频率、前向 relax 占原协议总时间的比例。不能由 29／32 的理论上界推算实际时间，也不能由减少写数推算总提速。

只有诊断发现一个明确的、保持采样集合且能显著减少实际归约次数的机制，才重访事件表示。成本判别需比较“省去的原松弛成本”与“新增事件生成、查询、过期、flush 和历史 choice 存储成本”；各项实际单价和目标收益空间仍 UNKNOWN。若只是将每次现有点松弛换成一条点事件，或机会集中在很短范围，停止该具体实现投入。任何小信号仍需固定版本、配对总压缩时间和独立 runner 确认。

## 任何精确变换的最小义务

- **边集合和生成时状态。** 保持候选区间划分、lo／hi 强制点、原 nextl、续接、skip、所选 backward extension／截短边；成本使用生成时的 `base/lc/dcc`。`2249–2252` 会动态换价，旧事件不能到消费时重新读取新价。模型保留了 old=32、竞争者=50、new=80 导致赢家翻转的反例。
- **可观察点完整。** `2156` 读当前 `pa[i]`，`back_best/d_back_best` 读历史成本，`backtrack:1039–1058` 读历史 choice。到达最小值必须在这些读取前完整且保留原 choice；无须在来源尚未生成时提前应用。原前向边的目标都在处理游标之后，这一点可用于证明，但不能忽略 skip 跳转时未消费的目标。
- **ring 及 epoch。** 保持 `2151–2153` 远端槽初始化；`open_chunk:1075–1081` 将起点置零并清空后续 258 槽。skip、CHUNK 和结束回溯见 `2222–2238`、`2244–2247`、`2255–2259`。旧 epoch 的未来事件必须失效，历史已消费 choice 在相应回溯前仍可读。仅按目标模 8192 排队没有这些保证。
- **完整状态反馈。** 保持 forward plan 及回溯时序，才能据此保证相同 `lf/df` 更新、后续在线价格和 `d_tally`／后向多遍种子。首遍“只用于统计”不是允许改变输出的等价证明；后续规划不保证消除种子差异。
- **正式桥梁 UNKNOWN。** 现有 Lean `relax_run_spec:446–448` 和 `d_parse_spec:3395–3399` 的局部后置条件是 `True`，这里不能读成旧／新递推等价证明。新表示要迁移终止／边界证明并运行精确源码的官方提取、原 obligation、公理检查与 round trip。此次 Python 仅核对上述有限 helper 模型，不证明其所有状态在真实 parser 可达，也不证明 Rust 实现、整份 token 同一、性能或 gate。
