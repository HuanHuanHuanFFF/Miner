# B11 端点 entropy-fit 后接原完整 Huffman DP

缺口：B10 longest-only 缓存统计让真实 7 个 A 文件全部减少 token 却增加字节，总损失 12,213 B／0.039518 pp；原 encoder 已证伪该统计来源。其新统计仅约 13.8 ms，仍有成本余量测试更强的统计过程，但减少 old 调用数本身不是速度或收益。

实质修复：统计首遍改为原 A 的 entropy DP，只保留每条长度域的 lo／hi／全局长度码末端；它仍比较 original cost[next] + length price + distance price，因此考虑后续路径、距离码价和当前块价格目标，比直接取最长匹配保留更多原目标。端点集合固定，无阈值／passes 扫描。原 A matcher、全部候选缓存、块上下文和最后完整 a_dp_pass 保留；末轮长度域没有剪边。端点首遍得到的真实路径经原 a_walk 拟合频率，再原平滑 Huffman 构价并执行完整末轮。

新增成本与限制：端点拟合仍扫描其范围的每个输入位置和每个原候选，维护整份原 cost/ch 缓冲，并查询固定端点表；它会比 greedy 统计更贵。相应扫描、价格加载、缓冲初始化、频率 walk、Huffman 构价和原最终 DP 都计入实际成本。它不保持首遍最优值或完整 token 等价；原 encoder/decode 和真实两轴决定价值。

旧负例：R7 seed1 和 R10 廉价 D 种子也使用过长度端点，未取得前沿；R18 carry-model／one 跳模型刷新使质量回退。本次是针对 B10 已实测统计质量失败的单次修复，基于已完整生成的 A 匹配图，并不改 D 首遍的搜索／记录，保留 A 未裁剪的完整末轮。这是作用阶段与数据覆盖的重访差异，不是端点采样的新发明，不抹去旧反例。

最小实验及成本上限：一份候选、一个 20 分钟 public native，先原 encoder／decode 的 28 文件质量及实际 A matcher／新端点拟合／原末轮／walk／构价粗成本。原 #552 和 mandatory public514 作参照；新批次交付前执行 round4.validate 与 round26-preflight 的完整逻辑，再由 root 对顶层冻结输入执行正式生产预检。无完整 proof／paired／正式上传。

改变选择的结果：若非 A 路径变化或 decode 失败，诊断；若未明显追回 B10 损失，则停止这条拟合修复，不层层恢复原架构。若质量恢复且实际工作成本仍有空间，按当时最新完整官方快照作二维条件重放，再决定原协议总时间。目标仍为稳定 5%／10%；有稳定正份额但未达目标仅作备用，不能报达标。原 Lean 暂为未适配草稿，新 helper／端点拟合接口要在有用结果之后云端提取及分层证明。
