# DEFLATE 技术规则与看板维护

共同执行约束与所有授权以根 [AGENTS.md](../../../AGENTS.md) 为准。本页由原根规则中赛道专属部分迁移，保留原有技术要求；文件内路径以 `competitions/deflate/` 为起点。正式新提交当前已关闭，历史结果与回执仍保留。

## 研发与证据

通用研究循环、预算、公开来源取舍、官方文件完整性及原始回执保护统一执行根规则；这里仅补充 DEFLATE 特有的度量和交付要求。


- 优化以稳定的竞赛奖励池份额为优先目标。候选取舍依据冻结后跨 runner 独立复测的观测最低值、中位数、范围、零份额次数、达标次数及同源码参照一致性；保留全部反例，峰值仅作线索，样本达标比例不解释为正式成功概率。
- 每轮优化开始及研究中前沿明显变化时，检查新公开的提交源码，优先学习和优化曾有较高官方竞赛奖励池份额的版本，包括退出前沿后开放的代码。核对官方源码可用性，保存取得的 Rust／Lean、提交 ID、作者、查询时间及哈希；用历史官方快照核验其份额和可观察的持续情况，缺失记 UNKNOWN。刷新榜单本身不算完成源码调查，公共预测峰值不充当历史正式高份额证据。
- 候选在 `candidates/` 修改，参照来源和作者归属保留。官方 contract、encoder、gate、pins 及 `sources/` 阅读副本保持原版。
- 正确性结论绑定精确 Rust／Lean 哈希及官方重新提取、原始 obligation、公理白名单和 round trip。复用证明或有限等价检查不能替代完整 gate。
- 性能使用固定语料和配对 incumbent 的总压缩时间，保存逐文件测量、工具链与 runner 信息，按官方两轴公式复算；CPU 微优化观察同字节对照与跨运行波动。
- 每次研究阶段简报、候选比较和收尾报告，同表列出候选的竞赛奖励池份额、时间轴 X（逐文件总压缩时间中位数／配对 incumbent 中位数，倍）及大小轴 Y（逐文件压缩后／原始字节比例，%）；两轴按官方口径聚合，越低越好。份额对应同一行实际用于评分的两轴、参照及快照／时间；公共实测、校准投影和正式成绩分列，缺测写 UNKNOWN。
- 计算或报告当前排名与份额前，查询最新官方榜单和评分规则，保存原始响应、SHA-256、快照 ID 及计算／查询时间，再按同一最新快照逐块重算候选；联合加入时重新计算前沿与归一化。历史估算单列；查询失败时保留旧值及其时间，最新结果标为 UNKNOWN。

## 提交看板维护

- 每轮研究收尾刷新看板；获授权的正式提交取得 ID 后，将 ID、轮次与精确候选目录加入 `docs/submissions.json`，运行 `python scripts/update-dashboard.py`。结果待定时保留 UNKNOWN，正式结果到达后再更新；未提交候选只记研究报告。
- 刷新全部历史提交的同一官方快照，归档原始响应、时间及 SHA-256。初始份额保留最早可核验记录与快照，缺失写 UNKNOWN；当前份额使用 `payable_weight × 100%`，累计 α 使用官方 `bounty_earned_alpha`，钱包到账另据链证据。查询失败保留旧值及其时间并说明失败，不能将缺失写成零。
- 交付前检查看板、初始记录和新回执一致，运行 `python scripts/project.py check`，将看板及证据随本轮按已有授权提交／推送。维护看板本身不授权正式上传、签名或资金操作。
