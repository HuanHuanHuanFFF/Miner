候选把父本的 `all checkOne → map encode → FloatArray.mk` 改为顺序 `prepareLoop xs k out`：每项只绑定一次 `d := encode x`，从这个 `d` 窄化、导入并检查 raw word，通过后把同一个 `d` 直接 `push` 到预分配的 `FloatArray`。循环中没有中间 `Array Float`、运行时 `.data` 或每步 `Option` 包装。

## 3. 实际运行代码

以下代码直接存在于交付的完整 Kernel；不是假设接口。`encode` 和 `read` 沿用父本。

```lean
@[inline] def checkOne (x : Binary32) (d : Float) : Bool :=
  (ExecFloat.Binary.ofFloat32 d.toFloat32).raw.1 == x.raw.1

def prepareLoop (xs : Array Binary32) (k : Nat) (out : FloatArray) :
    Option FloatArray :=
  if hk : k < xs.size then
    let x := xs[k]
    let d := encode x
    if hcheck : checkOne x d = true then
      prepareLoop xs (k + 1) (out.push d)
    else none
  else some out
termination_by xs.size - k

def prepare (xs : Array Binary32) : Option FloatArray :=
  prepareLoop xs 0 (FloatArray.emptyWithCapacity xs.size)
```

`k` 与 `out` 是独立运行参数。归纳不变量只用于证明，没有放入运行时结构、元组或成功值。每次成功循环直接尾调用，只有失败处分支 `none` 和终点 `some out` 两处 Option 构造点。这里计的是源码构造点，不是声称每个构造都对应一次堆分配。

固定 Lean 4.34.0 中确实存在 `FloatArray.emptyWithCapacity`、`push`、`size`、`get`；它们的逻辑定义分别给出空数组、追加、大小及元素读取。[S3] 本候选直接调用这些已存在的 API，没有添加外部实现。

### bmm 接线

```lean
def bmm (batch m n p : Nat) (A : Vector Binary32 (batch * m * n))
    (B : Vector Binary32 (batch * n * p)) : Vector Binary32 (batch * m * p) :=
  match CheckedFloatArray.prepare A.toArray with
  | none => originalBmm batch m n p A B
  | some AF =>
    match CheckedFloatArray.prepare B.toArray with
    | none => originalBmm batch m n p A B
    | some BF =>
      Vector.ofFn fun q =>
        let (b, i, j) := bmmDecodeC m p q.val
        CheckedFloatArray.dot n ((b * m + i) * n) (b * n * p + j) p
          A.toArray B.toArray AF BF
```

A 失败会立即选择 `originalBmm`，不会求值 B 的准备。B 失败时同样传入原始 A/B；AF 和失败的 B 前缀不会成为回退输入。只有两者返回 `some` 时才进入 checked dot。全部转换、检查、预分配、失败清理和后续回退均留在每次 bmm 调用内。

## 4. 证明的完整结构

下面解释代码内已经写出的证明，不代表本环境已通过 Lean 核验。

### 4.1 单项检查没有要求 opaque 数值往返定理

对本次实际算出的 `d`，检查的是：

```lean
(ExecFloat.Binary.ofFloat32 d.toFloat32).raw.1 == x.raw.1
```

`checkOne_eq` 先用 `beq_iff_eq` 把 raw word 的布尔相等变成相等命题，然后依次使用 `Subtype.ext` 和 `ExecFloat.ext` 得到整个 `Binary32` 相等。后者在固定 FloatLib 中正是由 raw 字段相等推出可执行值相等。[S6]

这一步没有使用 Float 的数值 `==`，也没有断言 `(x.toFloat).toFloat32 = x`。`Float32.toFloat` 和 `Float.toFloat32` 可以保持 opaque：运行时检查提供本次存储值所需的等式。

### 4.2 前缀不变量

源码定义：

```lean
def Prefix (xs : Array Binary32) (k : Nat) (out : FloatArray) : Prop :=
  out.size = k ∧ k ≤ xs.size ∧
    ∀ i, i < k → ExecFloat.Binary.ofFloat32 (read out i) = xs.getD i posZero
```

三项各有用途：

1. `out.size = k` 表示已存入的元素数恰好是已处理元素数。
2. `k ≤ xs.size` 与循环结束条件一起给出终点 `k = xs.size`。只有终止时的 `¬ k < xs.size` 不够。
3. 每个 `i < k` 的读取等价负责内容正确性。这个条件没有被长度条件替代。

初始 `out = FloatArray.emptyWithCapacity xs.size` 的逻辑大小为零；元素条件因 `i < 0` 不可能而成立。容量只服务运行时分配，逻辑不变量不把容量当元素数。

### 4.3 push 对旧位置和新位置分别证明

`push_size`、`get_push_lt`、`get_push_eq` 在 theorem 内对 FloatArray 的逻辑表示分情况，再使用固定核心库的 `Array.size_push`、`Array.getElem_push_lt` 和 `Array.getElem_push_eq`。[S3][S4]

- 对 `i < out.size`，push 后读取仍等于原位置。
- 对 `i = out.size`，push 后读取恰好是实际传入的 `d`。

`read_push_lt`、`read_push_eq` 随后以 `congrArg Float.toFloat32` 把存储 Float 的相等传过窄化函数。**这是任意函数都满足的相等保持性**，并不展开窄化函数或假定它有数值往返性质。

`prefix_push` 将 `i < k+1` 分成 `i < k` 与 `i = k`。旧位置使用上述保留性和旧前缀；新位置使用本轮 `checkOne_eq`，再由 `Array.getElem_eq_getD posZero` 转为原输入的总读取形式。

表示展开、`cases out` 和 Array 元素定理仅出现于证明。准备计算定义没有调用 `.data`，因此没有为了证明在运行时把整个 scalar array 重新装箱。

### 4.4 循环终点和越界正零

`prepareLoop_sound` 对 `xs.size - k` 递归：

- 当前检查通过：用 `prefix_push` 构造下一前缀，再应用递归证明。
- 当前检查失败：`none = some prepared` 不可能，因此不能伪造成功不变量。
- 已到终点：由前缀上界和循环否定条件推出 `k = xs.size`；由 `some out = some prepared` 得到 `out = prepared`。

终点中，`i < k` 的情况直接使用前缀逐项等价。对 `i ≥ k`，长度等式同时给出 `i ≥ out.size` 与 `i ≥ xs.size`：左侧未修改的 `read` 返回 `Float32.ofBits 0`，右侧 `getD` 返回 `posZero`。此处按父本使用的正零定义归约完成，不涉及 Float64 的 opaque 往返。

最终两条对外接口为：

```lean
theorem prepare_size_eq (xs : Array Binary32) (prepared : FloatArray)
    (h : prepare xs = some prepared) : prepared.size = xs.size

theorem read_prepare_eq (xs : Array Binary32) (prepared : FloatArray)
    (h : prepare xs = some prepared) (i : Nat) :
    ExecFloat.Binary.ofFloat32 (read prepared i) = xs.getD i posZero
```

其中 `prepare_sound` 同时证明长度与全部索引读取等价，这两条接口只是取相应合取分量。

### 4.5 从成功事实闭合无条件 bmm_spec

`bmm_spec` 对 A 的准备结果作 `cases hAF`，在成功分支再对 B 作 `cases hBF`。两个失败分支直接使用未修改的 `originalBmm_spec`。

全部成功分支中的：

```lean
have hA := CheckedFloatArray.read_prepare_eq A.toArray AF hAF
have hB := CheckedFloatArray.read_prepare_eq B.toArray BF hBF
```

已经给出 `∀ i` 的两个真实读取不变量，随后传给未修改的 `CheckedFloatArray.dot_eq`。剩余步骤沿用父本的逐输出外延、`index_address` 和 `referenceBmm_spec`。导出的 `bmm_spec` 对所有 batch/m/n/p、所有输入向量无条件成立的**证明源码**已给出；它没有额外的 finite、非零维或外部 sound 前提。

## 6. 特殊值与维度边界

| 情况 | 本轮结构的处理 | 证据边界 |
|---|---|---|
| ±0 | 检查原 raw word，负零被改变时不能仅因数值等于零而通过 | 不宣称实机转换已测 |
| NaN payload / sign / quiet-bit | 若实际读取导入改变原 raw word，则准备失败，使用原始输入回退 | 没有把转换层 NaN 规范化当完整算法结果 |
| Inf | 准备是否成功仍由 raw 检查决定；后续 dot 的 finite 守卫保留 | 无 unconditional roundtrip 假设 |
| subnormal | 同样逐字检查；改变位型时回退 | 没有 flush-to-zero 假设 |
| prepare 空数组 | 直接到成功终点，size=0，无逐项 encode/check | 仍可能有零容量数组/Option 的运行时常数成本 |
| 成功数组的越界索引 | 两边都为精确 +0，任意 Nat 索引均包含在接口中 | 不限于测过的若干索引 |
| `n=0` 且输出非空 | A/B 均为空，未改 dot 从 +0 开始并立即结束 | 属于通用证明源码覆盖 |
| `batch=0` | 输入和输出长度均为零 | 未添加 shape 特判 |
| `m=0` | 输出/A 可空，B 仍可非空，按本轮范围继续准备 B | 不顺带优化零输出路径 |
| `p=0` | 输出/B 可空，A 仍可非空，按本轮范围继续准备 A | 不顺带优化零输出路径 |

即使准备成功，计算也可能产生非 finite 的最终 dot。这个情况下仍执行父本保留的原始精确 fold；准备检查不能替代最终守卫。

## 7. 完整成本分析

令 `a=A.size`、`b=B.size`、`S=a+b`。以下是源码求值/数据流计数，不是 CPU 指令数或耗时估计。

### 7.1 A/B 全部准备成功

| 项目 | 父本 | 本轮候选 |
|---|---:|---:|
| `encode` 求值 | `2S` | `S` |
| 窄化、导入、raw-word 检查 | `S` | `S` |
| 显式中间 `Array Float` 的元素 | `S` | `0` |
| 最终 FloatArray payload 元素 | `S` | `S` |
| 准备遍历 | check；map；构造器读取 mapped array | 一遍检查并 push |
| 成功 Option 源码构造 | 无 | 每个输入终点一次 |

FloatArray 中的存储数据仍是 double payload，A/B 合计 `8S` 字节，不计对象头、对齐和分配器开销。变化针对中间 pointer array 以及为它存储 Float 所需的装箱路径；不宣称 Binary32 输入和校验过程中所有对象或所有临时 Float 装箱都消失。

固定运行时的 `lean_float_array_mk` 遍历输入 pointer array 并逐项拆箱到 scalar array；`lean_float_array_data` 则反向分配 pointer array 并逐项装箱。本轮源代码去掉前一条中间构造路径，也没有引入后一条物化路径。[S8]

### 7.2 A 在零基位置 f 失败

两种结构都只对 A 的 `f+1` 项作 encode/check，都不需要 B 的准备。候选额外请求容量为 `a` 的 FloatArray，并存储前 `f` 个已通过元素；失败时丢弃该前缀。父本此时尚未进入任何 FloatArray.prepare。

### 7.3 A 成功、B 在零基位置 g 失败

两者都对 `a+g+1` 项作 encode/check。候选已经完整存储 A，并为 B 分配、存储其前缀，共 `a+g` 次成功 push。父本仍没有进入成功条件后的两次 prepare。

因此，这次变换没有“所有路径工作都减少”的性质。失败密集或晚失败输入可能回退成本更高；空输入和非常小的矩阵也可能受到 Option、Nat 控制和 push 常数成本影响。父本给定的 `0.09633×` 不能用来推算本轮的新比率。

## 8. 预期生成 C 的形态

以下只是依据 Lean 源码与固定运行时推导的数据流示意，**不是已生成 C，不是一个 C 性能实验**：

```text
out := scalar_array_with_capacity(xs.size)
k := 0
while k < xs.size:
    x := xs[k]
    d := encode(x)                 // 一个可复用的 double 临时值
    if raw(import(narrow(d))) != raw(x):
        release(out)
        return none
    out := float_array_push(out, d)
    k := k + 1
return some(out)
```

真实生成代码需要核对五件事：

1. 同一项 `encode` 的结果在检查和存储之间复用，未重新引入重复转换。
2. 准备路径没有 `lean_float_array_mk`、`lean_float_array_data`、Array-of-Float builder，亦无专为该中间数组出现的 `lean_box_float`。
3. 循环内部没有每项 `some` 构造，递归是尾调用或循环形态，前缀证明擦除。
4. `out` 在 push 时保持独占所有权。固定运行时在共享时会复制 scalar array；**预分配只解决容量，不自动解决共享复制**。[S8][S9]
5. 检查失败时的释放、已经完成的 AF 和 B 前缀成本仍在完整 bmm 计时内。

本源码没有显式保留历史 `out` 的运行时闭包；后续 `Vector.ofFn` 捕获的是两个最终只读缓冲区。但实际引用计数和是否存在反复前缀复制，仍须生成 C 确认。

### 有限模型实际覆盖

`symbolic_prepare_model.py` 把 encode→narrow→import 替换为本轮自造的任意纯 raw-word oracle，只检验控制流和不变量记账，不执行 Lean 或真实浮点转换。

- 24,992 个 prepare 情况：五词字母表、长度 0–4、32 种拒绝集合。
- 12,800 个 A/B 配对情况：确认 A 失败后不准备 B，两种失败都返回原始输入对象。
- 81 个维度长度组合：batch/m/n/p 各取 0–2。
- push 前后检查旧元素对象保留、新元素就是已检查对象；成功读包含边界外索引及 `2^32`。
- 构造“负零被归零”“NaN payload 被规范化”“最小 subnormal 被清零”的 oracle 时，raw 检查按预期拒绝。

这些有限例不能判定固定 Lean 的真实转换会接受哪些位型，也不证明 Lean 定理能通过 elaborator。它们只支持控制流与数据复用设计的独立检查。

## 10. 一次最小固定环境验证请求

请求开发侧在**已存在的固定环境**做一个验证任务，不安装另一工具链、不改官方配置/依赖/比较器、不正式提交：

> 输入为本报告冻结的父本 SHA 与候选 SHA。先编译完整候选并保存编译错误或生成 C；随后用未修改的官方 `--slot full` gate 核验候选的四项义务、kernel replay、公理与原数值合同。C 中重点检查一次 encode 临时值、直接 scalar-array push、无中间 Array Float/.data、无每步 Option、无共享前缀复制。最后将父本与候选作为同一完整 bmm 配对的两端，固定输入、机器、CPU、seed 和既有轮次，保留按用例和按轮数据；转换、校验、分配、释放、失败前缀和最终非 finite 回退全部计入调用。返回 exact SHA、完整日志、每用例结果及原始 receipt；任何未运行阶段继续标 NOT_RUN。

同一任务要观察正常成功输入、零维以及真实转换会拒绝的特殊词。若某特殊词确实被拒绝，将首次拒绝放在 A/B 的首、中、末位置比较完整调用成本；不能伪造转换函数来获得“实际失败路径计时”。

官方固定 gate 的通常测量对照是随附参考。**两份各自对参考的 ratio 相除，不自动等于直接父本/候选配对证据。** 若当前环境只能提供这两份 gate receipt，应保留它们并把直接配对标为未完成。这个区分不要求修改官方配置。[S2]

包内的 `work/compile_existing.py` 是可直接送给已有环境的最小编译辅助：

```bash
python3 work/compile_existing.py /absolute/path/to/fixed-official \
  --output /absolute/path/to/new-r2w04-compile-output
```

它核对官方 HEAD、固定文件 SHA、FloatLib materialized HEAD 和 Lean 版本；只在输出目录写 olean/C/日志，并用单独生成的诊断文件打印新接口及四项规格的公理依赖。不安装、不更新依赖、不改候选、不派发 CI，也不声称替代 full gate。该辅助在本环境只通过 Python 语法检查，真实 Lean 执行仍为 `NOT_RUN`。

官方完整 gate 的调用形态，已从固定 `gate.py` 核对：

```bash
cd /absolute/path/to/fixed-official
.venv/bin/python gate.py --slot full /absolute/path/to/R2-W04 \
  --verdict /absolute/path/to/receipts/r2w04-full.json
```

路径替换为开发侧实际目录即可；候选目录只需其中的 `Kernel.lean`。诊断文件和来源快照不得拼进候选。若编译/公理/数值任一项不通过，先记录完整诊断并修复本轮范围内问题，不能把已知父本通过替代候选验收。

```bash
python3 work/static_checks.py
python3 work/symbolic_prepare_model.py
sha256sum -c SHA256SUMS.txt
```

这些脚本不需要安装 Lean。运行会重写相应派生 JSON；完整包的原始 SHA 清单应在修改文件前先核验。`assemble.py` 用于需要重建时，普通验收无需先运行。
