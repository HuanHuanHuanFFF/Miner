# R2-W03 数学独立审查

状态：**数学推导成立；有限整数模型诊断 PASS；本文没有宣称 Lean 已编译或 native 速度改善。**

## 1. 结论及最小有意义支持域

对任意 normal binary32 原始位 `u`，令

\[
s=u\gg31,\quad E=(u\gg23)\mathbin{\&}255,\quad
f=u\mathbin{\&}(2^{23}-1),\quad M=2^{23}+f.
\]

在逐操作 RN-even、gradual-subnormal 的 binary32 语义下，

\[
\operatorname{neg}^{s}\!\left(\operatorname{RN}_{32}
\left(\operatorname{RN}_{32}(M)\,2^{E-150}\right)\right)
= \operatorname{ofBits}(u),\qquad 1\le E\le254.
\]

这里的等号可提升为逐位等号：乘积是有限非零 normal，因此数值与符号唯一确定 bit pattern；不涉及将 +0 和 -0 视为相同的漏洞。重要区别是此式在 IEEE 模型中可证明，与固定 Lean pin 是否提供足够的 `UInt32.toFloat32` 定理是不同问题。

首个窄候选只需支持 `102 <= E && E <= 151`，共 50 个正缩放常量，并另行支持原始位 `u == 0` 的 +0。这个 normal 域覆盖本题全部 dense/wide 分布；relu 的 +0 需单独快速返回已经证明的 +0 常量，且之后仍执行原来的有序 add。将 +0 留在原函数回退会让约半数 relu 元素保留原调用，不能宣称同样消除了热循环调用。

## 2. 完整数学证明

1. `0 <= f < 2^23`，故 `2^23 <= M < 2^24`。每一个这样的整数都可用 binary32 的 24 位有效数精确表示，因此正确舍入整数转换满足 `RN32(M) = M`。
2. `1 <= E <= 254`，故缩放指数 `q=E-150` 满足 `-149 <= q <= 104`。这一区间内所有 `2^q` 都有精确 binary32 表示：`q=-149..-127` 时为单一非零 fraction bit 的 subnormal，`q=-126..104` 时为 fraction=0 的 normal。
3. 精确实数乘积 `M*2^(E-150)` 就是 binary32 编码 `E,f` 的正值：`(1+f*2^-23)*2^(E-127)`。它已可表示；最大边界为 `(2^24-1)*2^104`，正好是最大有限数，不溢出；最小边界为 `2^23*2^-149 = 2^-126`，正好是最小 normal。
4. 乘法正确舍入到 binary32 时，已可表示的精确乘积不变，没有误差、半 ulp 案例或双重舍入问题。整数转换与乘法分别精确；不是把两次不精确舍入假定能抵消。
5. 原生 negation 对有限非零值精确翻转符号，得到 `s,E,f`。normal 的表示唯一，故输出位与原位相同。

证明甚至不依赖 RN-even 的具体 tie 行为，因为被允许的每一个操作结果都精确可表示；但整个任务的 sum/mul 仍保持指定 RN-even 语义。

## 3. 因子位型和边界

精确缩放值的 bit pattern 为

\[
P(E)=\begin{cases}
1\ll(E-1),&1\le E\le23,\\
(E-23)\ll23,&24\le E\le254.
\end{cases}
\]

| E | 因子 | 因子位型 | 说明 |
|---:|---:|---:|---|
| 1 | `2^-149` | `00000001` | 最小 subnormal；与 M 的积仍 normal |
| 23 | `2^-127` | `00400000` | 最大的本公式 subnormal 因子 |
| 24 | `2^-126` | `00800000` | 因子开始 normal |
| 102 | `2^-48` | `27800000` | 任务 wide 下界 |
| 124 | `2^-26` | `32800000` | 任务 dense 下界 |
| 130 | `2^-20` | `35800000` | 任务 dense 上界 |
| 150 | `1` | `3f800000` | M 本身就是结果大小 |
| 151 | `2` | `40000000` | 任务 wide 上界 |
| 254 | `2^104` | `73800000` | 与最大 M 相乘恰为最大有限值 |

如果希望避免把 subnormal 当乘数，额外守卫 `E >= 24` 足够。这样不是数学上必须回退 E<24，而是主动缩小 native/环境证明义务。原合同已要求 gradual-subnormal；若实际环境启用 DAZ（将次正规输入当零），在 `u=00800000` 上该公式会把因子 `00000001` 当零，输出 `00000000`，直接失败。不能用 normal 输入这一事实推导所有中间输入都 normal。

## 4. subnormal、±0、Inf/NaN

### subnormal 与零的合法扩展

对所有有限位型可改为

\[
M=\begin{cases}f,&E=0,\\2^{23}+f,&E>0,\end{cases}
\qquad q=\max(E,1)-150.
\]

然后仍计算 `neg^s(RN32(M)*2^q)`。当 `E=0`，`M<2^23` 的转换精确，乘积是 `f*2^-149`，恰为目标 subnormal 或 +0。最后用真正 negation 翻转符号可得到 -0。其证明需包含 zero 的符号规则及 gradual underflow，而不能只用实数相等。

初候选完全可以保留 E=0 回退，仅为 +0 加单独常量路径。这样代码与 proof 更窄；不妨碍全输入正确性，因为其余原位仍交给原函数。

### nonfinite

E=255 必须离开上述有限重构域。本文不定义 FloatLib 原始 NaN payload 的传播规则；`Float32.ofBits` 自身的 NaN 规范化也不意味着可以提前规范化 raw sum 的输入。证明“转换函数等于原来的 ofBits”只准许替代已有转换点，不能额外放宽原 sum/native 快路的有限性守卫。

`ofBits` 回退在转换层必须原样执行；若完整计算的 raw NaN 语义需要原 FloatLib 路径，仍保留该完整路径。Inf 也不需要为此次窄研究新增数值重构分支。

## 6. 可考虑的替代表达

### 避免 subnormal 因子的两阶段 normal 方案

\[
y=\operatorname{RN}_{32}(\operatorname{RN}_{32}(M)\,2^{-23}),\qquad
x=\operatorname{neg}^{s}(\operatorname{RN}_{32}(y\,2^{E-127})).
\]

`y=M/2^23` 精确且在 `[1,2)`；第二个因子 `2^(E-127)` 在所有 normal E 下都是 normal；最后结果也精确。此顺序没有中间溢出或 subnormal。但需要额外一次乘法，且没有解决整数转换的 Lean bridge，应作为 E<24 的可选稳健扩展而非默认性能胜者。

### 真正无表、无乘法的极窄整数域

当 `150 <= E <= 158` 时，`N=M << (E-150)` 可在 UInt32 中容纳，并且是恰好可表示的 binary32 整数。即使 N>=2^24，其低位零仍使其只需 24 位有效数，所以 `UInt32.toFloat32 N` 仍精确。再施加符号即可。这是无表的一次转换版本，但只有 wide 的 E150、151 两档命中，dense 完全不命中；为它增加专门分支未必有经济性。不能把 `N<2^24` 误当所有精确整数转换的必要条件。

### 符号放入缩放常量

使用 `(-1)^s*2^(E-150)` 的有符号表，并直接相乘，同样精确；它可省显式 negation，却需更大的表/索引，是否更快由 codegen/测量决定。此变化没有数学障碍。

## 7. ordered sum 的接入条件

将转换替代限制在已有正常 native 路径内。对每个输入位 u，先证明转换函数在快路域等于旧 `ofBits u`，其他输入定义上执行旧函数。因此在相同 accumulator、相同输入索引上，原先的那一次 RN32 add 得到相同结果。按索引归纳可替换整个循环，而无需 add 的结合律、重结合、树归约、FMA 或预转换数组。

这个局部替代证明与 bmm 的原序 mul/add 同理。它不会自动证明现有 native 算法对所有 raw NaN 语义正确，也不扩大题目声称已完成的有限分支证明。

## 8. 诊断证据

`exact_dyadic_checks.py` 仅用 Python 整数实现 RN-even dyadic 编码和有限乘法。实际运行：

- 每个指数 187 种结构化 fraction，含低位边界、每个二次幂附近、最大 fraction 附近；两个符号。
- 原 normal 方案与安全两阶段方案：94,996 cases PASS。
- 通用 finite 公式（含 subnormal/±0）：95,370 cases PASS。
- E150..158 的 UInt32 移位整数路径：3,366 cases PASS。
- 6 项反例已固化为精确十六进制断言或有明确语义前提的条目。

此运行不是穷举 2^32 位型，不是 Lean proof，不是 native runtime benchmark，不能据此推算性能。
