# 对 root 提出的整数移位重构的独立审查

## 结论

**三种公式全部成立**，包括所有被守卫允许的 fraction、sign，而非只对整尾数或给定样本成立。关键应采用“有效二进制位数不超过 24”的整数转换充分条件，而不是较强且不必要的 `N < 2^24` 条件。较大的整数也可能精确表示，只要多出的低位均为零。

### 通用分块定理

给定 normal 位型的 `M=2^23+f`。选起始指数 L、块宽 B，并对 `E>=L` 置

\[
j=\lfloor(E-L)/B\rfloor,\quad r=(E-L)\bmod B,\quad
N=M2^r,\quad C_j=2^{L+Bj-150}.
\]

在整数左移没有定宽溢出、C_j 可精确表示的条件下：

1. N 的有效位数仍不超过 M 的 24 位，故正确舍入到 binary32 的整数转换精确。
2. `N*C_j = M*2^(r+L+Bj-150) = M*2^(E-150)`，精确乘积恰为目标 normal。
3. 因此一次整数转换、一次 binary32 乘法、精确符号操作即可得到原 bit pattern。

若使用 W 位无符号整数，保证 `B <= W-23` 足以容纳全部 r∈[0,B−1]；若还希望整数保持在对应有符号类型正范围内，足够 `B <= W-24`。取 `L>=24` 时全部 C_j 至少 `2^-126`，没有 subnormal 因子；最大 E≤254 也使 C_j 不会过大。

## 1. dense 专用 UInt32 单常量

守卫 `124<=E<=130`；`r=E-124`；`N=M<<r`；固定 `C=2^-26`（bits `32800000`）。

- `0<=r<=6`，`N < 2^(24+6)=2^30`，UInt32 左移绝不溢出，且最高符号位保持 0。
- N 可有 30 个整数二进制位，但至少 r 个末尾零，只有至多 24 个有效位，转换精确。
- `N*C = M*2^(E-124)*2^-26 = M*2^(E-150)`。
- 所有 dense normal 均命中；relu 对 +0 单独处理；wide 超出该域应原样回退或进入另外的已证路径。
- 此方案消除 factor 的输入相关查表，仅需要一个合法闭合的常量值，代价是一个可变整数左移及较大精确整数转换的证明。

数学上可以扩到 E132（r≤8，N<2^32），但 E132 的某些 N 最高 bit 为1，代码生成形态可能变化。继续无守卫扩至 E133 必败：输入 `42800000` (64)，M=`00800000`，r=9，UInt32 左移回绕为0，重构输出0。

## 2. UInt32 八个指数一组

守卫 `24<=E<=254`；`q=E>>3`、`r=E&7`；`N=M<<r`；`C_q=2^(8q-150)`。

- q∈[3,31]，共 29 个因子；r∈[0,7]；N<2^31，全为有符号32位正范围。
- C 的指数范围−126..98（每次增加8），全部 normal。
- 若需要从0开始的表下标，用 `j=(E-24)>>3`，相同 r，`C_j=2^(8j-126)`。
- wide E102..151 对应 q12..18，共7个因子；dense E124..130 对应 q15或16，共2个因子。若坚持 dense 单常量，上一节的有偏起点124更合适。

## 3. UInt64 三十二个指数一组

守卫 `24<=E<=254`；`d=E-24`；`q=d>>5`、`r=d&31`；`N=(M:UInt64)<<r`；`C_q=2^(32q-126)`。

- q∈[0,7]，共8个因子；r∈[0,31]；N<2^55，因此 UInt64 不溢出，且永远小于2^63。
- 所需因子精确为 `2^-126, 2^-94, 2^-62, 2^-30, 2^2, 2^34, 2^66, 2^98`，全部 normal。
- wide E102..151 只使用 q=2、3；dense E124..130 全用 q=3，因子为 `2^-30`，r=4..10。
- 数学上可对 actual wide 建立两常量分支，不必8元素通用表；条件选取的运行成本和最终 C/汇编需要独立核查。
- UInt64.toFloat32 是与 UInt32.toFloat32 不同的 Lean bridge 义务。不能从已证明的24位UInt32整数转换直接声称此项已证明；也不能把 `Float32.toFloat` 再 `Float.toFloat32` 的不透明往返当替代。
- 因 N<2^55，在支持 signed64→binary32 单指令的平台上，数值范围允许使用该路径；是否真正生成这种路径只由实际 codegen 决定，本文不声称编译器一定消除 UInt64 cast 的其他分支。

## 4. 证据与机会边界

已扩展 `exact_dyadic_checks.py` 并实际执行，仍由独立整数 RN-even 模型作比较：

- UInt32 dense 单常量：2,618 cases PASS（7指数×双符号×187 fractions）。
- UInt32 分块：86,394 cases PASS（231指数×双符号×187 fractions）。
- UInt64 分块：86,394 cases PASS（同域）。
- 新增 E133 UInt32 移位回绕反例。

这些替代确实减少了数学上需要的缩放常量数，不涉及 sum 重组，也不需要预转换数组。它们是否胜过每元素 ofBits 调用仍未知；“没有查表”不能推出“更快”，而新增的整数转换精确定理可能比原 M<2^24 的定理更难在固定 pin 中落地。
