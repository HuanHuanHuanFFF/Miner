## 结论：未观察行跨 batch 本身不构成位值错误

设 T0 是前四个状态，T1 是后四个状态。每步分别是：

- T0[l] := RN32(T0[l] + RN32(A0[k] * B[k,l]))；
- T1[l] := RN32(T1[l] + RN32(A1[k] * B[k,l]))。

T0 的新状态不依赖 T1、A1 或其他 lane 的状态。因此从八个精确 +0 初值开始，对 k 归纳，T0 与单独计算 A0/B 的四条有序链逐步相等。这个等式无需 A1 finite，也无需 A1=+0。对合法 r=1 输出，另一条同样的投影证明使用真实第二行地址。

奇数 m 的最后行对中，2*h=m−1，所以 base1=(b+1)*m*n。非最后 batch 时它的完整 n 项恰为下一 batch 的第一行；最后 batch 时 base1=A.size，所有 k≥0 的 Nat getD 都返回默认 +0。前者即使读到 Inf、任意 NaN 或非零有限值，也只改变该 tile 未观察的 T1。

**局部非干扰不能误写为整个 bmm 对下一 batch 输入不敏感。** 下一 batch 的真正输出当然可以依赖那些输入；这里仅证明当前 tile 的有效第一行不受其未观察第二行状态影响。

最小正向见证：batch=2,m=n=p=1，A=[1,+Inf]，B=[1,1]。第一个 tile 的未观察第二行有效列为 +Inf，未观察填充列可为 NaN（Inf×0）；第一个合法输出仍为 1。实际第二个输出为 +Inf。这个例子反驳“未观察行非零/非finite必然污染第一行”的说法。

## 必须满足的独立性条件

1. 每个 s0..s7 从精确 +0 开始，更新只读取自己的旧值、其所属 A 行和对应的 B 字段。
2. 从 q 解码后选择的是 `4*(i%2)+(j%4)`；h=i/2、g=j/4 每个 batch 内重新解释。
3. 只对这个合法输出的原生结果做 final-finite 接纳；非finite回退用这个输出自己的原始行/列地址。
4. 未观察 lane 不输出，也不复用成下一 batch 的输出；其状态不能进入有效 lane 的计算或接纳证据。
5. 两条 A 流的 word 快路证明必须对应同一个 Nat 循环。原始 Nat 地址/span 不成立时进入该 Nat getD 路径；不能把已经回卷的机器地址拿来冒充原地址界。
6. 不以 FMA、首项乘积播种、浮点重结合或无条件跳零替代规定的有序乘后加。

这些是具体的证明/实现检查点，不是新增最终 bmm 规格前提。正确实现应在其定义和证明内部满足它们。

## 哪些“共享 guard”会错，哪些只会多做回退

- 若“八路任一非finite”触发所有有效输出各自按原始行/列精确回退，数值可以仍然正确，只是发生额外回退。不能将这个保守版本描述为必然位错。
- 若从“某个 lane finite”推导另一个 lane finite，证据无效。上述正向见证的同一 tile 已同时包含有限和非finite状态。仅凭 aggregate 判定不能调用父本针对指定结果的 finite 桥。
- 若共享回退还共享了错误的 baseA/baseB、直接广播一个结果、或从 native 缓冲重建原始输入，则会破坏对应输出的证明。以下给出不依赖 NaN payload 传播细节的分类反例。
- 原生 NaN 与原软件 NaN 的 payload 是否一致，不能凭某次硬件表现推出。父本 finish 的回退明确使用原始 Binary32 A/B；本轮不猜某条 NaN 输入的精确传播 payload。

## 规定舍入图的四个短校验

- 首项播种的符号零反例 R6：RN32(−0×1)=−0，但 RN32(+0+(−0))=+0。不能把数学上同为零当作 bit-level 等价。
- FMA 反例：shape=(1,1,2,1)，A=[−1,1+2^-23]，B=[1,1−2^-23]。规定第二步先乘得到 1，再加 −1 得 +0；若第二步融合，则精确残差 −2^-46 可表示，结果为 0xa8800000。
- 重结合反例：shape=(1,1,3,1)，A=[2^24,1,−2^24]，B=[1,1,1]。规定顺序结果 +0；若改成 2^24+(1−2^24)，结果 1。这里没有提出新的展开实现，只给完整调用的反例输入。
- 次正规校验：shape=(1,1,1,1)，A=[0x00000001]，B=[1]，合同输出仍为 0x00000001；清零次正规会得到 +0。

## 尾行的机器字边界

在奇数 m 的最后行对，base1=(b+1)*m*n。若 b+1<batch，base1+n−1<A.size（n>0）成立，允许 word 流读取下一 batch 的第一行；这并不赋予该流一个当前 batch 的合法输出行身份。

若 b+1=batch，则 base1=A.size，末元素 span 必不小于 A.size；第二条流检查必须失败。退回 Nat getD 后，该未观察流返回 +0，仍不影响有效第一行。即使第一条流可用 word uget，也不能直接删去第二条流的实际读取证明。

原始 Nat 的完整 span 与 USize 上界必须先得到正确证据。示例说明为什么不能改成“回卷后的末地址比较”：令抽象 W=8、batch=m=1、n=5，则 A.size=5<W、base1=5，原末地址 9 越界，而回卷后 1<5。这不是当前组织的反例；当前组织明确检查原始完整 span，并会拒绝。实际 USize 的同型参数是 n=W/2+1。这里只作整数边界说明，不声称分配或执行了巨大数组。

## 对完整调用的最小否决检查建议

优先把 R1/R2/R3/R4/R6/R7、上面的 FMA/次正规见证送进实际完整 bmm，与原始软件参考逐位比较。再加入 A/B 的非规范 quiet/signaling/负号 NaN 位型，例如 0x7fc12345、0x7f812345、0xffc54321；预期一律由固定参考生成。对奇数 m 的中间 batch 与最后 batch 都要覆盖，才能同时观察“跨到下一 batch”和“末尾 getD 默认值”两个路径。

任何一个合法输出位型不一致即可否决当前实现。若只在正确性外询问性能，必须比较包含准备、转换、缓存、输出、回退与释放的完整调用；本审查不给速度预测。新实际源码/Lean日志未提供，本轮没有已观察到的候选失败，也没有候选通过结论。
