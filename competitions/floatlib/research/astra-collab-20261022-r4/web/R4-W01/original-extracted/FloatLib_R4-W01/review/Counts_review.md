# R4-W01：独立源码计数与最小否决请求

状态：本文只核对任务给定布局的数学计数与验收设计。已执行 Python 整数计数，原始结果为 `counts_result.json`。没有执行 Lean、候选、C、汇编或计时；这些项目全部 **NOT_RUN**。没有实现热循环、改 benchmark 或扩展块尺寸。

## 1. 默认形状计数

令 β=batch，G8=(p+7)/8，H2=(m+1)/2，G4=(p+3)/4，除法取 Nat 整除。

- 1×8：块数 T8=β*m*G8，k 迭代 I8=T8*n。
- 2×4：块数 T24=β*H2*G4，k 迭代 I24=T24*n。

对 β=2、m=50、n=100、p=50，有 G8=7、H2=25、G4=13。用户给定各项数量与下表一致。

| 项目 | 1×8 | 2×4 | 解释 |
| --- | ---: | ---: | --- |
| 有效输出 | 5,000 | 5,000 | β*m*p |
| 有效 MAC | 500,000 | 500,000 | β*m*n*p，计分分母应保持这个量 |
| 结果 F8 块 | 700 | 650 | T8 / T24 |
| k 迭代 | 70,000 | 65,000 | I8 / I24 |
| 含填充的 MAC | 560,000 | 520,000 | 每迭代八条链 |
| A 总读取 | 70,000 | 130,000 | 每迭代一条 / 两条 A 流 |
| B 包读取 | 70,000 | 65,000 | 每迭代一个包 |
| 每次取一次的不同 B 字段 | 560,000 | 260,000 | 每迭代八字段 / 四字段 |
| B 记录 | 1,400 个 F8 | 2,600 个 F4 | β*G*n |
| B 缓存标量字段总数 | 11,200 | 10,400 | 8*1,400 / 4*2,600 |
| B 填充字段 | 1,200 | 400 | 有效 B 都是 10,000 元素 |
| A 有效转换 | 10,000 | 10,000 | β*m*n |
| B 有效转换 | 10,000 | 10,000 | β*n*p |
| 有效输入转换合计 | 20,000 | 20,000 | 不含本来就能直接构造的填充 +0 |

默认 m=50 为偶数，因此 2×4 没有额外行填充；它的 20,000 个额外 MAC 全来自尾列。1×8 的额外 MAC 为 60,000。一般奇数 m 时，2×4 仍计算八条链，包含未观察的第二行；不能将一般形状的 padded MAC 写成 β*m*4*G4*n。

20,000 是共同输入准备阶段的有效元素转换数；若某输出触发精确回退，回退中的原始标量运算及其可能存在的转换必须另计，不能藏进这个准备阶段计数。

这些计数不是字节流量、运行时分配次数或机器指令计数。

## 2. 260,000 次 B 字段读取的必要限定

2×4 每次 k 只需要四个不同的 B 字段，每个值供两行使用。因此 **260,000 是字段各取一次并复用的源级需求数**。

如果两个行更新表达式都直接重复书写 v.s0、v.s1、v.s2、v.s3，源码中会出现八次字段投影，即 520,000 个投影表达式。显式绑定四个局部 B 值可以清晰表达复用意图；编译器是否合并重复投影、是否保存在寄存器、最终发出几条 load，仍需要实际生成代码证据。本轮没有这项证据。

因此报告可确认“每迭代只需四个不同 B 值”，不能未经观察确认“只有 260,000 条内存加载指令”。A、B 包的源级读取计数也同样不直接等于 load 或引用计数指令数。

## 3. 更少 MAC / B 字段，同时增加哪些工作

- A 读取由 70,000 增至 130,000。两条 A 流意味着更多数组元素访问与地址状态；若数组元素采用装箱表示，也意味着更多取得元素对象和解包的源级需求。实际引用计数增减、是否借用、是否消除解包都未观测，不能逐读取机械加上一对 inc/dec。
- B 对象从 1,400 个 F8 变为 2,600 个 F4；记录数增加，但标量字段总量由 11,200 降到 10,400。对象头、数组指针槽、构造及回收费用与字段 payload 变化方向不同。没有实际表示/分配数据时，不能声称总字节减少或增加了某个精确量。
- 结果仍是 F8。块记录由 700 减至 650，保存的八字段结果槽由 5,600 减至 5,200，但都要输出 5,000 个有效标量。
- 两种布局仍使用同一个 (b,i,j) 解码；2×4 额外需要 h=i/2、r=i%2，并把行内 lane 映射到 4*r+l。原来的列除余数换成按四列分组。是否有除法化简、公共表达式复用或选择分支消除，不能从源码计数推断。
- B 值复用提供两条独立乘加链使用同一操作数的机会，但更多 A 访问、对象及解码开销可能抵消收益。这里不预测加速倍数。

## 4. 最小完整调用否决请求

### 正确性先行

先冻结精确候选 SHA，使用不变官方环境执行原有正确性验收。任一已有硬门槛或逐位比较失败即可停止，不先用性能掩盖。

除原有 raw 校验外，最小定向集合建议覆盖：

1. **batch=2,m=1,n=1,p=1**：同时观察“非最后 batch 的未观察 row1 读取下个 batch”和“最后 batch 的 row1 越界”。例如 A 位型为 `[0x3f800000,0x7f800000]`，B 位型为 `[0x00000000,0x3f800000]`。合同有效输出为 `[+0,+Inf]`；首个块的未观察第二行会算 Inf*0。这个未观察 NaN 不得改变首个有效 +0。
2. **batch=2,m=3,n=2,p=5**：同时覆盖局部行对、跨 batch 尾行、最后一个 k、列尾块和所有有效 lane 的解码。给每个真实行/列不同数据，避免相等数值掩盖地址错误。
3. **空输出与 n=0**：保持原参考支路；可用 batch=0 和巨大 Nat n 检查不提前进行机器字截断或准备。这里的巨大形状不用实际分配非空矩阵。
4. **独立性变形检查**：仅改变下一 batch 第一行的原始 A（依次选有限非零、Inf、带 payload NaN、±0、次正规），前一 batch 奇数尾行的有效输出必须逐位不变；下一 batch 本身的输出仍逐位对照原参考。该检查直接针对跨 batch 未观察读取，不要求猜测共享旗标的实现。

具体 NaN payload 的预期应取固定原始参考，不能用通用宿主浮点或“所有 NaN 相等”替代。单次存在未观察非finite不能自动证明共享守卫错误：若共享守卫只让有效输出额外走正确的 raw 回退，语义仍可能正确，只是费用增加；若它替换/混合结果或使用错误原始行，则会失败。

### 性能只看既有完整调用

不修改 benchmark，不增加 C surrogate。使用现有完整调用 runner，做最小的 baseline A → 新候选 B → baseline A 的交错对照，记录三个默认域与原有汇总规则、精确构建 SHA、原始时间和两次 A 的漂移。A 是本轮给定的已验证 1×8 起点，B 是新 2×4 的完整候选。

所有准备、转换、B 打包、结果缓存、输出选择、非finite回退和按既有计时边界计入的释放都要保留；分母用 500,000 个有效 MAC。不能用 520,000 / 560,000 个填充 MAC 当分母制造 ns/MAC 改善。

明确否决条件：

- 任一既有正确性或硬性能门槛失败，停止此版本。
- 若完整调用在所有默认域均被前后两次 A 支配，差距也明显超过同轮 A 的漂移，则没有继续晋升本版本的证据。
- 若 B 只在内层计时好看，而完整调用无收益，应按完整调用结果停留，不把部分工作节省当成已获速度提升。

一个 A/B/A 周期足以提供早期否决证据，但不足以在噪声相近时宣布新冠军。是否继续复测遵循现有验收流程，本文不另造统计门槛或要求每个域必须改善。
