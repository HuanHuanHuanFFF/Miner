- 当前轮完成路线整理与有界只读摸底，未新增候选 CI。前一小时窗口保持已结束，不将这次规划解释为自动延长该窗口。

## 公开起点调查

本次读取官方完整源码树，调查版本 21e42d8f93cd3ecdf5dc4a84c7951ad4c17b185c；CI pins 保持原样。文件、Git blob SHA、内容 SHA-256 和原文见 [sources.json](sources.json)。

- 官方 full/incumbent 已经是机器字 add/mul 加张量组合，不适合笼统归因为“还在使用大整数”。
- 官方 full/baseline、bmm/fast 及 add/tuned/mul/fast 可作对照和证明桥接资料；没有在已查官方树中找到 #174 的精确源码，不把示例当冠军。
- 官方 textbook-unproved 给出保留舍入信息的不同加法结构，但 fast-path 证明缺失，不能直接作为可提交版本。官方文档明确部分对齐／舍入引理是 private，改算法要另建论证。
- Berkeley SoftFloat 的 addMagsF32 与 f32_mul 展示右移并保留 sticky 信息、定宽乘积、固定舍入／打包机制。它们是 John R. Hauser 的 C 实现，版权与许可头已保存；它们不提供本赛道 Lean 证明，NaN、零和舍入策略需要按 pinned contract 重新核对。
- FloatLib 的已记录 /source 路由返回 404；当前 API 文档将这一通用路由归于 DEFLATE，尚无经过验证的 FloatLib 源码下载入口。这不是可以靠重复重试解决的下载故障。可合法取得的新增冠军代码仍值得查，未取得不阻止独立内核探索。

## 优先路线与首个判别实验

| 路线 | 实质变化与收益来源 | 最小有效实验 | 最早证明障碍与转向条件 |
| --- | --- | --- | --- |
| P0：测量与编译归因 | 区分算术、包装／分配、索引和编译器公共子表达式；确认张量极低计时是否反映实际单次执行 | 在临时 runner 保留生成 C／IR、分配与调用观察；官方 gate 不改动，另用独立诊断调用观察新输入与重复输入，并计入转换成本 | 诊断结果与正式计分分列。若只见预计算移出计时，记录其边界，不把 checksum 时间解释成矩阵乘法吞吐 |
| P1：张量原始位执行底座 | sum 使用 UInt32 位状态；bmm 在内循环复用位状态、地址和步长，减少 Binary32 包装与 getD；多个输出可交错，但各输出 k 顺序保持 | 保持同一 add/mul 算法，只换表示／循环，对照完整十二类；同时观察 dense/relu/wide 与分配成本 | 先证明位状态对应同一逐项累加、索引覆盖任意合法维度；若转换／分配抵消收益，缩回可复用的局部表示，不能把搬运排除在计时外 |
| P1：重建常规乘法内核 | 正常有限数的 24×24 位乘积直接走固定宽度规格化、一次最近偶数舍入与字段打包；完整替代通用 roundProduct 热路径，非只换 log2 | 独立候选：正常输入且结果在受保护范围时走新内核，其余使用已认证 fallback；先测三类 mul 和 full，并核查真实 guard 覆盖率 | 首先证明固定移位与一次舍入的位结果等价，覆盖进位及正常／次正规边界。若 tiny 主要落回旧路径，另评估次正规规范化，不能仅以 near-one 成绩推进 |
| P2：重建加法数据流 | 对齐到有界尾数并保留 guard/round/sticky，分开同号加法、异号消去与大指数差；减少左移扩张和通用规格化 | 先实现有清楚守卫的正常数同号路径，再检查 cancel 的正规化；三类 add 与 full 对照；提前编译最难的对齐／sticky 舍入引理 | 证明成本高于旧 helper 复用。若关键引理闭合不了或分支覆盖很低，保留已证子域并换另一分解，而非无限扩写 tactic |
| P2：零与特殊值的共享快路径 | 将可证明的零、单位值及状态分类用于算术和张量循环，避免高频通用 fallback；仅按值与语义条件分支 | 统计三类输入及真实中间态的覆盖率，独立消融判断是否降低 full 总时间 | +0/-0、抵消、NaN、0×Inf 和次正规结果是首批证伪点。不能无条件跳过零项；有反例即收紧守卫或回退 |

两条 P1 原型在实现与测量上独立：一条保持算术只换张量执行结构，一条保持张量只换乘法。其收益只有在实际组合版本重新计时后才可合并。加法路线在首批诊断期间继续准备关键证明，不因 CI 等待而停止独立分析。

## 首批执行顺序与去留

1. 刷新冠军身份、政策及可取得源码，锁定对照。源码不可得时，在报告中保持“对冠军比值 UNKNOWN”，用官方分项与内置基准配对作筛选坐标。
2. 用一次有界诊断查明包装、索引、分配和计时边界；诊断应产生生成代码位置、调用路径与足以区分解释的读数，而不是先建立庞大工具系统。
3. 产出“张量位执行”和“常规乘法重建”两个机制独立的原型，优先完成各自最难的证明桥接。未完成证明时只能标 benchmark 筛选，不标完整通过。
4. 按 full 总时间、十二类退化及证明可完成性选推进对象；发现只对单个输入类好看时补一个判别实验。对总指标机会不足且没有新依赖证据的方向降级，保留适用条件。
5. 加法 GRS 路线承担追近前沿后的主要增量；它的高证明成本通过关键引理检查点管理，不用简单重试替代机制变化。
6. 候选组合后冻结精确文件，运行完整官方 gate，再用未参与选择的种子／新 runner 确认。研发争取明显超过官方 3% 门槛的余量，具体余量由实际波动决定。
7. 只有与届时冠军匹配的直接比较或正式结果才能支持竞争力结论。正式上传与费用仍按根授权边界办理，本次规划未执行这些操作。

## 降级与排除

- 旧 fastLog2 两层判断、单条舍入条件或纯属性扫参保留为对照／后期收尾，不占主研究队列。它们在当前差距下缺少足以改变选择的收益证据。
- 单独 bmm 的小改不作为夺冠主线；它先服务追赶底座。其余路径固定时的 0.76% 理想上限已给出直接反证。
- 改加法结合顺序、把 bmm 的逐步乘加换成 FMA、近似浮点、仅按测试形状写答案，不满足逐位契约。
- 硬件 Float32／SIMD 指令若不能在允许依赖与公理中建立逐位桥接，就不进入主实现；它可以是可行性问题，不能先假定有证明。
- 等待冠军源码不作为整个开发的停止条件。未知源码下载入口与正式上传权限分别记录，不能由其中一项缺口扩大另一项授权。
