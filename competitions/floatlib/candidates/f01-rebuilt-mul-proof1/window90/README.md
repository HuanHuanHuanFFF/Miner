## 实验怎样改变了方向

- 实现了相互独立的乘法数据流、张量位状态、地址循环和加法子域，而非继续扫描旧 log2／舍入 helper 的细碎变体。每一失败和后续证明修复都绑定精确源码与真实作业。
- 原始位累加的收益有限。早期从失败构建后取得的 C 实际可能是缓存基线，不能归给失败候选；诊断已改为在成功候选的构建层清理前回收 C，并保存 Kernel／C 哈希。
- 地址方向的两次失败是证明化简超时。最后用函数等式与一条具体索引等式完成全部维度的证明，运行算法没有因此改变。
- 加法两个具体版本均退化，GRS 原型的 add 分项约慢 28.2%。这些结果反对继续投入这两个版本，不构成“所有定宽加法／GRS 无效”的结论。
- pinned FloatLib 的零操作数路径会回退精确 dyadic 运算；这给出了下一条应检查的完整加法数据流，但本轮没有完成该路径的逐位证明或性能实验。
- 为取得可用反馈，本地 CI 适配增加了完整编译输出、仅编译诊断和官方 --bench 筛选模式。官方 gate、contracts、bench 与 pins 保持原版；只有 full_gate=true 才是完整验收，筛选成功不算证明成功。诊断适配曾有 errors(text,status) 参数不匹配，原始失败已保留，后续修正并预检。
- 新 manifest 初期使用 kernel_sha256，和既定自检字段 candidate_sha256 不兼容；已补齐兼容字段及生成器，Kernel 字节未改变。本地静态检查与原始回执字节校验另行记录。
