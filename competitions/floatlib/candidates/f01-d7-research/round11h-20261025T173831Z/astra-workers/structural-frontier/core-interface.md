# Temporal packing core and proof boundary

`TemporalCore.lean` is an actual 2-column runtime core, not a complete submitted kernel. It defines a 32-byte native-field record, a ceil(n/4) packing vector, a full-block path with one n bound test for four k steps, a separately guarded 0–3-element tail, and a runnable dot-pair entry. It uses only ContractTensor and safe existing definitions. It does not alter Submission or copy the baseline. The source contains actual Lean proof bodies for packing projection and exact four-step lane expressions; these are NOT_RUN.

`OrderedBlocks.lean` gives an unbounded proof attempt for arbitrary state and arbitrary ordered step: four-at-a-time grouping with the original serial tail equals the original serial loop. Consequently its claim does not need real-number associativity, finite-input assumptions, numerical equality, or NaN simplification. It also states the quotient/remainder partition that maps each k to exactly one stored field. Again, bodies exist but have not been checked by Lean.

To integrate into the retained B2 path, the remaining concrete obligations are:

1. Specialize packet_get to each of eight fields under that field's k<n premise. getD defaults remain exactly those of the original B2 pack, including the unused second lane when p is odd.
2. Relate the actual Pair-valued loop to blocks4 with state Pair and per-k two-column update. The full path has the identical parenthesized operations; the partial path uses precisely the valid first1/2/3 steps. No padding MAC is executed. A finite symbolic model checked201960 output lanes and3332340 ordered MAC pairs but is not this universal Lean bridge.
3. Project the two state fields to the old R15PackedB2.loop_s0/loop_s1 or NativeFinal.dotLoop equations. Preserve the original raw arrays and Packed10.finish for payload-sensitive replay. Use the original RowStream Prefix/output proof chain after this local equality. Do not replace the public bmm_spec by a weaker native-result proposition.
4. For a worthwhile compiled candidate, inspect actual selected C: one32B block record, one borrowed record access per four k values, native fields, no temporary B2 records, no Float32 boxing, and no reconstructed block at each consumer. The current prototype has Nat indices and raw-A getD/ofBits calls; neither is claimed removed. An eventual USize translation is a separate index proof, not present here.

Per pair-group with n=4q+r,0<=r<4, the current packed-B request model is24n+24 bytes. New B2K4 requests48*ceil(n/4)+24 bytes. It saves48q-24 when r=1,48q when r=2,48q+24 when r=3, and48q when r=0; for n=1 it costs24 more, n=2 ties. It performs2n valid raw B conversions, stores2*(4*ceil(n/4)-n) inactive fields, and allocates ceil(n/4) records. Valid A conversions and two MAC chains remain n per output pair. The public entry must continue handling zero dimensions and retained fallback routing; this standalone core supports n=0 but does not claim a new dispatch policy.

On the three completed public plans, a conditional extension to current B1/B2/F10 prepared routes reduces modeled B record counts171521→49278,150026→41020,167457→44691, and modeled B array+record requests4.294→2.554MB,4.077→2.522MB,4.303→2.431MB. The B1 old path has one global array and12-byte logical float-box requests before allocator rounding; the new per-batch block layout adds batch array headers. These counts aggregate each input's preparation once, are not25-round totals, do not measure allocator traffic, and assume the underflow shortcut misses. They include representation variants not implemented by the B2-only core. Original inputs, outputs, vector outer arrays, closures, allocator size classes and replay costs are excluded. Do not infer a speed ratio from these numbers.

The useful new question is now narrow: is current whole-time dominated by the allocation/pointer/index work that these temporal blocks can actually remove? Old R16's new A4 panel allocation is not sufficient evidence, because this proposal is compared with retained B2/F10. Without that measurement, this is a reusable lower-object representation prototype, not a justified high-priority10% whole candidate.
