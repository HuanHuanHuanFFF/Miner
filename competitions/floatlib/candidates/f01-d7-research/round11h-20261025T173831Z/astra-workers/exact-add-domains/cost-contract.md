# Caller cost contract for the exact cancellation component

Decision context: **retain as a component of a shared normal adder; PARK an independent new wrapper**. The proposed arm has no native conversion and no toBits boundary, but the domain guard and normalization are real work. This document imposes no new permission or CI request.

The exact B2 source is `622d8394a7127e93dcaf992c62c6dfcff7208d212738409a5e34525dfafd1a58`. Its public ADD at Kernel.lean:3023 converts both input words, performs native ADD, tests self equality to reject NaN, and calls `ofFloat32` or the original NaN fallback. It has no specialized exact cancellation arm. Independent archived C selection from completed run 40168024176 follows `BENCH_PLAN -> Bench.Suite.run first argument -> closed__1 -> lam__0___boxed -> lam__0`, not a guessed lam suffix. The selected body starts at original line 75 and hashes to `7888289dc32091fa85b4dab9af02f11081a133b51cd23dd7c486036f9b9f269f`.

On the ordinary fast-decode path that body has two UInt32-to-Float32 casts, two borrowed scale-table reads, two scale multiplications, one ADD, one self comparison and one final toBits. On normal inputs with exponent below 24 the converter takes its general `ofBits` path instead. Static occurrences of those alternative calls are not all executed on one input. This is generated-C evidence, not cycle counts or the exact timed ELF.

The exact-cancellation hit can remove that complete conversion/arithmetic/finish path. It pays for any fields not already available, sign opposition, magnitude order, gap and N guard, one shift/subtract, zero handling, highest-bit normalization when needed, output-kind decision and field packing. Unlike R16's one-cast route, a hit has **no external toBits call and no raw fields live across that call**. This is the meaningful mechanism difference. New C/assembly and net timing are UNKNOWN.

For a useful integration, the caller should provide both normal eligibility and the already extracted fields, sorted words/mantissas and low exponent once. A concrete scalar internal interface is `exactClose(sHi, eLo, d, mHi, mLo)` under proved opposite-sign, normal and order premises; it returns the word on `d<=1 && N<2^24`. There must be a single computation of `N`, and one retained `sHi/eLo`. A new independent wrapper around B2 starts without those shared premises and must charge all extraction/normal checks even when it falls back. Returning Option/tuples is not assumed allocation-free; verify the selected generated callback, or use local control flow whose erasure is observed.

The shared normal-adder dispatcher must account for the hit and miss paths together:

`new_time = sum_hits(new_guard + new_exact_path) + sum_misses(new_guard + fallback) + caller/layout_delta`.

Where a common caller already paid a field/order check for another arm, charge only its actual incremental work; never declare the entire wrapper free. Conversely, if fallback repeats fields or sorting, include it. R16 f7f's real selected C recomputed order/exponents around its conversion and retained raw inputs across toBits. Its full-gate negative (ADD 1.87392, whole 1.29455) is a reason to demand this caller inspection; it neither times nor refutes the present no-conversion arm.

**Highest-bit interface:** fixed Lean commit `293d5d0c0c3f3dded4688b3ccd6a33939ac5102b` exposes `lean_uint32_log2` as a static-inline while loop, dividing by two until below two. It is not a documented CLZ primitive. `lean_nat_log2` is an external exported function with the same loop for scalar values. Here `N<2^24` and the result are scalar Nat values, so Nat does not imply heap allocation; the external boundary still exists unless separately shown eliminated. No compiler changes or externs are proposed.

The sampled nonzero hits would execute source-level UInt32.log2 means 18.57, 18.65 and 16.15 iterations across the three old draws. These are counts implied by the header loop, not executed machine-cycle measurements. Exact B2 already has `FastMul.fastLog2` and `fastLog2_eq`: six binary-search steps at 32/16/8/4/2/1; the first is mathematically redundant for zero-extended `N<2^24`, but actual C elimination must be checked. This existing bounded-step implementation is the appropriate proof/cost starting point if integration is later selected. No new normalization implementation was built in this stage.

A future shared-caller probe must inspect the actual selected callback and prove that accepted exact paths avoid native conversion, table reads, toBits and generic rounder calls; that the high/low choice and N are not recomputed; and that misses pay only the intended checks before original B2 behavior. It must include all four unchanged obligations, source-size/policy constraints, original public timing and fresh independent confirmation if it reaches adoption. These are future missing validations, not completed work or authorization to start CI.

No direct SUM/BMM improvement is inferred: retained native accumulation bypasses public ADD on its common loops, while reference/replay paths may still call it. Coverage here measures only old scalar ADD input generation. Any propagated public-function effect requires the actual whole package.
