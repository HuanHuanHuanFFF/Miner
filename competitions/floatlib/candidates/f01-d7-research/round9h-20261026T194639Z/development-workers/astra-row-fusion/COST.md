# B16：完整成本与可证伪条件

本探针父本为 c36bc250 / 241509B；新源 8adff3a0 / 249605B。只实现 B16 packet/pack、四链 loop 和等于两条原 Dual loop 的证明尝试，没有接新 public 路由。下列新成本均为源码条件模型；没有新 C、计时或采用结论。证据路径与完整 SHA 见 `static-check.json`。

令 R=batch*m、T=ceil(n/4)、G2=ceil(p/2)、G4=ceil(p/4)。仅在继承的 3≤p≤8,n>1,m≥4 中，并且 2G2=4G4，即 p=3,4,7,8 时考虑换路。p=5,6 保留父本。四行方案没有实现：它会要求多个列组的 F8 结果跨输出保留，或改随机写数组，而本窗没有证据支持其额外写出与证明成本。

| 完整调用中的工作 | 父本 A4+B8 | B16 目标 | 状态 |
|---|---:|---:|---|
| 有效 A 转换、A4 记录 | R*n、R*T | 完全相同 | 现成 A4 复用，未减少准备/析构 |
| B 读取/转换含原奇列虚lane | batch*2G2*n | batch*4G4*n | 目标域相同；不是仅 p*n |
| B 包记录 | batch*G2*T | batch*G4*T | 减半；payload从32增至64B |
| 内层 A4 包读取 | R*G2*T | R*G4*T | 减半，不是时间证明 |
| 内层 B 包读取与循环控制 | R*G2*T | R*G4*T | 减半；每次四链 |
| 累加标量 MAC | R*2G2*n | R*4G4*n | 原序、数量相同 |
| 终态记录 | R*G2 个 F2 | R*G4 个 F4 | 每四列累计请求32→24B；单个存活结果16→24B |
| finish、原字NaN replay、UInt32装箱、输出push | R*p | R*p | 必须全部保留 |

B16 对每个 k 保持四列字段相邻。`low/high` 只用于证明及独立定义，不在数值 loop 中构造 B8；生成 C 必须确认实际热路径也不调用它们。`loop_eq` 同时关联低两列与高两列的整条 Float32 累加轨迹，因此无效奇列含 NaN/Inf、跨原行读取或默认零都不能污染其它lane。父本 `runDot` 先计算双lane，`emit min 2` 才截去奇数最后列；新域没有扩大这一虚计算范围。k 尾只执行有效 1/2/3 步，绝不将零padding送MAC。行不融合，因此 m 尾行不存在新padding。

64位固定runtime条件模型：ctor头8B，Array头24B，槽8B，恰长容量。两B8+槽为96B，一B16+槽80B，每四列每k块减少16B；若完整packB直接替代旧缓存，每对列组的两inner数组头与两个outer槽64B变32B。**这尚未含closure/callback、allocator class、对齐、引用计数、Nat临时量或RSS。** A4与原raw A/B驻留完全保留；F4单结果峰值比旧单F2多8B。不能因累计请求减少就宣称峰值/耗时减少。

完整接线必须先建一次新 B16 缓存，再按行/列组连续 emit；不能先建旧 B8 再复制为 B16，也不能每行/每输出 pack，否则这里的成本前提失效。无需结果 tiles、输出补零、随机set或行转置。group/row/column-prefix和public规格仍须新证明；当前仅6395B余量，是否足够及完整证明成本 UNKNOWN。

历史区别已核源和原生成代码：R16 2a937bb0 的A4B2机器字核本就无转换/分配，whole1.00785021/BMM1.04343738；R12 da09窄F4 full后whole0.99651且p05负，它的实际内核已经4-lane SSE、编译器2k展开、热体无call/栈访问。后者每k读boxed Float32 A和F4 B；新布局变为每4k一个A4/B16。这里没有“首次SIMD”或“首次无call”的新条件。R19 indexed-B2 9f7也已消除Nat/default热分支，仍有codec call；本次没有将旧USize提案改名，也不把它混入探针。R11 W01行融合原件哈希保留，原未编译状态不升级。

下一判别限一个精确statement/codegen诊断，由D排队：八根→两模块重放/允许公理→实际loop及pack caller。必须区分普通完整4k、有效尾、冷大Nat与终态；重点观察四条lane是否合成一个4-wide SSE序列、是否新增常规spill、实际B16是不是64B payload且无B8临时物。若机制未实现或接口不闭合，停止当前探针；若实现，只能说明值得比较完整调用成本，不能以指令数安排晋升。新statement耗时、完整接线证明时间及全gate耗时均UNKNOWN；worker自用CI占用0，03:10交付上限未延后。

主控的冻结输入覆盖估计为整个B2域约4–6%whole（本worker未重算），本结构子域更小。即便相应数值核2倍，也远不是10%整包，且准备/finish/replay占比未知。建议父方在核心机制真实成立后再决定是否值得剩余窗口内接线；否则下一有依据的瓶颈是这些不随列融合消失的完整生命周期，而非继续扫列宽。
