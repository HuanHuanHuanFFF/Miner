# 下一问题短提案：保持B8布局，把A缓存改成一次行内广播

**当前只保留为条件提案，不造源码/队列。** 优先等d765真实编译和完整成本。如果Dual的实际hot loop达到预期而新增A准备/释放抵消收益，再问：能否把一行内的循环顺序从“每个B2组遍历全部k”改成“每个4-k块只解码A一次，再更新所有真实B2组的标量累加状态”，从而消除整个A缓存生命周期？若Dual已达到采用门槛，应先完成确认，不为此分散CI。

存储继续使用精确c70c B8，不更换B packet列宽，不做宽度网格。G=ceil(p/2)≤4，只为实际存在的G组更新两条原序链；最多8个原生Float32累加器以标量参数存活，不用每块Array/Vector状态或F2装箱。各输出的k次序和每步乘后加不变；只交换独立输出间的调度。原finish、NaN原字回放、行主序输出和域外路径仍是证明目标。

| 完整调用内的差异 | c70c | Dual | 本问题的目标 |
| --- | ---: | ---: | ---: |
| A解码次数 | G·N | N（准备阶段） | N（行内k块） |
| 新增A缓存记录 | 0 | R | 0 |
| 新增A缓存数组/析构 | 0 | 整次一份 | 0 |
| B8准备与有效输出finish | 原样 | 原样 | 原样 |

机会是删除Dual真实新增的A构建、全局写入/重读和释放，同时保留跨G的A复用；并非声称原始C70的A分配被省掉。相反，转换返回到hot row路径，更多累加状态可能跨ofBits spill。缺失组条件、B组指针读取、输出选择也有成本；不允许通过多算未存在的组制造“无分支”成绩。

**历史差异已核。** R16 A4B2是跨四行、已有call-free core但还有panel/result-tile容器与尾行；本问题只处理一行并保留B8，避免其result tiles。旧全域F4/F8方案重打包B、全局nativeA.map、旧isFinite/full-replay和Vector writer；这些真实负结果不能直接搬成当前路由的测量，但足以禁止把“更多累加器”自动当优势。R11 no-packing控制改为逐输出DirectRows、重复解码两边；本问题仍共享B8和一次A块。旧storage screen的raw-A-one-group想法也明确留下跨call寄存器风险，因此不声称新颖或已有收益。

**最小可区分证据。** 被选后只做一个真实行caller的全输入投影接口：把最多8个scalar state各分量对应回c70c原两链，检查没有在每k块重新创建state对象。实际选中C/ASM必须显示A只解码一次/行/k、没有A缓存或状态容器、没有重复B准备，并把跨4次A解码的保存与输出finish的保存都记下。若SLP/标量参数降级成盒子、backedge对象或大量spill，先停；若实现成立，再测包含B准备/输出/清理的完整调用，不从对象消失直接宣布胜出。

本提案暂不达到“应立即启动新完整CI”的证据强度。它的触发条件是d765的实际成本定位，泛化整包上限仍UNKNOWN；当前不重开零/NaN证书、m分派或DeepSeek rowLoop。
