# Packed-B2: one concrete layout variant, no CI queued

Primary artifact: `Kernel-b2.lean`, SHA-256 `622d8394a7127e93dcaf992c62c6dfcff7208d212738409a5e34525dfafd1a58`,226829B. It is based on D's immutable b116 pair repair and adds `PackedB2.lean` (9458B, SHA `f7eb16da2047172b5b6c054bb74f7015633be393fa2fdebe2239825c3dc16047`). **Complete source/proof attempt, NOT_COMPILED; correctness gate and performance UNKNOWN.** b962, b116 and all prior receipts remain unchanged.

The representation premise is backed by actual fixed-version code, not an inferred box count. `b2-representation-evidence.json` records exact Lean commit293d5d0c0c3f3dded4688b3ccd6a33939ac5102b header, source SHA982c731a…, and the old generated C source/body hashes. The header's `lean_box_float32` calls `lean_alloc_ctor(0,0,sizeof(float))` then writes one native field. Exact83a captured C's Array.map/toFloat32 loop calls that box operation once per element. Exact9a Panel4.packA generated C instead allocates one16B scalar-payload record, writes four native Float32 fields, and has zero individual Float32-box sites. Hence a two-native-field B2 has a credible single-record representation; **the new exact B2 generated C is still unobserved**. The fixed header is by Leonardo de Moura, Microsoft2019, Apache2.0, with its original notice retained. No Lean runtime code was copied into the submitted candidate.

The one chosen layout is `Vector (Vector B2 n) (batch * ceil(p/2))`. B2 aliases the existing F2 type. A flat outer batch/pair index avoids an additional per-batch vector layer; each pair's inner vector stores k records contiguously. Packing computes tile batch/group/base before the inner k callback. The numeric loop receives that inner vector, reads one B2 record at k, and feeds its two native fields to the exact original two scalar chains. It no longer carries p/baseB for hot B indexing. A decoding, initial+0, ascending k, independent multiply/add sequence, terminal F2 result, emit, `Packed10.finish`, raw arrays and NaN replay remain the parent's algorithm via equality. The same2<=p<=8,n>1,m>=4 guard and outer underflow scan are retained.

The proof path is concrete and small: `tileIndex`/`packB_get` establish the prepared fields, generic `loop_s0`/`loop_s1` accept only a prepared-read invariant and project to `NativeFinal.dotLoop`, `loop_eq_original` joins those scalar equalities, and `group_eq -> row_eq -> output_eq` reuses the existing pair writer/Prefix/reference. There is no new IEEE lemma or unchecked assumption. The proofs cover arbitrary batch/n/p and empty vectors; actual dispatch remains total for every Nat shape. All proofs still require Lean acceptance.

Odd p is deliberately exact even for the **unobserved** second chain: packB uses the same total raw getD address as the old pair loop, including the next row/batch word or the final+0 default. It does not silently replace that field with zero. Consequently odd p incurs one extra native B decode per original B row, and keeps the existing extra unused multiply/add chain. The writer still emits only min2 remaining columns. Both-lane read/order checks include these cases.

Fresh local checks (`b2-validation.json`) recover b116 byte-for-byte by inverse insertion/routing change, check7560 packed both-lane reads,90720 ordered opaque-expression lane chains and2772 shape output layouts over batch0..3,m0..8,n0..6,p0..10. These are finite structural checks, not a Float32 oracle or Lean proof. All subprocesses were bounded by timeout5s; this check took about0.191s.
