The new route applies to `2 <= p <= 8`, `n > 1`, `m >= 4`. It maps B to native Float32 once per BMM and computes adjacent columns in pairs. Each ascending-k iteration reads and decodes one raw A element, then advances two independent native accumulators. Each active output keeps the original `Packed10.finish` and its original raw A/B addresses. The existing underflow-zero guard remains outermost; every other branch remains the exact parent. The p<=8 boundary is the parent's existing thin/direct shape family, not a newly searched threshold grid.

This is distinct from occupied R14 thin-B: that route caches B only for p<=2 and still computes one scalar dot per output. It is also distinct from old Cross, which builds a P12 array for each four-row block. This route has two accumulators, no global nativeA map, no P12, no cross-batch four-row layout, and no per-group F10 B packing. It is not the failed 2x4/2x8 or R11 4x10 candidate with a new name.
