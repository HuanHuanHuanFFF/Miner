# Raw scaled certificate: avoid materializing the normalized denominator

The normalized `WordGap128` helper is sound within its stated domain. It cannot be promoted to a raw layer-norm output checker merely because P fits128 bits and D fits64 bits. Its candidate mantissa M has24 bits, so P/D must already be near2^23. Concrete counterexample: P=3·2^93, D=2^30+1, source exponent−64 gives correctly rounded word3fc00000 (1.5), M=12582912,target exponent−23. The logical normalization shift is−41, so the normalized denominator has72 bits. The raw normalized checker rejects, while both scaled midpoint coefficients have only55 bits.

`ScaledCell.lean.inc` therefore proves a different actual endpoint. For arbitrary Nat P,D,M and independent Int source/target exponents, positive D, strict interior normal M and ordinary encoded-exponent bounds, its two concrete hypotheses are

`D·(2M−1)·2^target < 2P·2^source < D·(2M+1)·2^target`.

It derives normalized integer midpoint inequalities through public `Model.scaleByPowerOfTwo_real`, derives the **raw** floor logarithm as target−source+23, and explicitly reduces the actual `NativeBinary32.roundRatScaled` normal branch. Its conclusion is the actual native packed word. The normalization denominator may be arbitrarily wide **inside this theorem**, which is erased from executable code. This is not an assumed cell-soundness oracle, a cross-width native equation, or a copied former-champion congruence proof.

`ScaledWord128.lean.inc` supplies the executable check for128-bit P and D<2^38. It computes one `D·(M+M)` word product and obtains lower/upper coefficients by subtracting/adding D. Under M<2^24, both coefficients fit below2^63. Public `DyadicCompare.compareNonnegative128ToWord` then compares P at exponent source+1 against each midpoint at target. Its exact published theorem is connected through Dyadic rational order to the Real inequalities above, then to the actual native rounder.

One library cost detail matters: `compareNonnegative128ToWord` always keeps its nonzero-high-limb path in words, but delegates a zero-high-limb input to the64-bit comparator, which may fall back to arbitrary Nat shifts. The new `fastAllowed` checks that branch's exact shift/fit conditions **before calling either comparator**; a failed condition rejects the certificate. This preserves a bounded word arithmetic check even for a bad guessed exponent. It does not make integer exponent arithmetic, guessing, coefficient construction or fallback free. Actual generated code and selected caller still need inspection.
