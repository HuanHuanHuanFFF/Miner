# R13 exactDF per-case diagnostic first version

Entrypoint CLI is `profile-entry.py --upstream --kernel --out --plan`; the adjacent module exposes `run(g,kernel,out,public_plan,seed)`. Runtime source is fixed to DF `df5c61a0…7fb172`, official4b7e838, already exposed seed1224016 and pairs500000. The independent entry runs original intake/policy/statement only. It never runs score/kernel-replay/axiom admission, and its verdict is explicitly diagnostic-only/full_gate=false.

This version deliberately uses the established generated-C instrumentation/relink route rather than reimplementing tensor math in a Lean clone. It first runs the unmodified actual benchFull on the complete official drawn plan and preserves each original case's whole timing/checksum. It then changes only the disposable candidate-layer Submission C and uses the original recorded clang compile/link arguments, without changing Kernel, official bench/gate/contracts, options or compiler flags. Original and instrumented C, exact Kernel, commands/link responses, logs and object/binary SHA metadata are exported; ELF/object bytes stay in the runner layer and are not artifacts.

The instrumented executable is run separately for each exact original case, twice, with the official BenchSuite generator/case parameters and3 inner sweeps. Each case's checksum must equal the uninstrumented full-plan anchor. The pure bmm/sum root count must equal all checksum+timed sweeps (sum multiplies by original batch). Scalar cases receive the original/profile whole benchmark rows only. Input generation, caller checksum traversal and cleanup remain within the official whole benchmark boundary; pure kernel function timers do not pretend to include those caller costs.

Generated-C function probes cover root bmm/sum, available A.map, Packed10 B.pack, p2 cross-row combinedAB packing, native/word compute loops, output/finish helpers and NaN replay/suffix repair. Nested exclusive accounting prevents compute being counted again inside output. Timers start before `_start`, so a tail-loop goto does not probe every MAC. True recursive C functions are skipped and reported. Stage counters outside an active bmm/sum root are excluded. UnderflowZero/dispatch scans or fused regions without separate emitted boundaries remain root-exclusive/residual; a zero category is never claimed to have zero cost.

Stage totals aggregate checksum+all3 inner sweeps, while official benchmark rows are per-case fastest sweeps. They are different statistics. Per-case process/cache context, clock overhead, instrumentation and relink layout prevent these measurements from establishing formal gain, official stage shares or an adoption result. Inseparable boundaries are explicitly UNKNOWN.

Hard module budget is300 seconds including preparation/compilation/link/profile commands; each command also uses min(its cap, remaining). This is below the agreed1000-second entry measurement ceiling. No job/runner/memory caps are raised.

`profile-test.py` freshly passed on actual saved014 generated C as a syntax/interface fixture: every selected return and before-tail-label entry is covered, all required phase families have definitions, and checksum mismatch/missing stage/stack imbalance/wrong call count/invalid exclusive totals are rejected. That fixture is42c and is **not** DF runtime or performance evidence. ExactDF Linux/Lean/clang diagnostic execution remains NOT_RUN until Root dispatches the new wrapper. Source hashes and complete local coverage are in `profile-local-tests.json`.
