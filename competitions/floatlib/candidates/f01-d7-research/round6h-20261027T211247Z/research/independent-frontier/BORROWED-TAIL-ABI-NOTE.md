# One explicitly borrowed native-ABI probe

Borrowed-tail-ABI.lean.inc is1400B, SHA680ca1b3676bf0e3e71d92b94a858ad87c1481b41e878bab5b0fae0aeedf1495. It is ordinary mutual safe-definition source with written termination proofs, **NOT_RUN**, and is not a SUM/BMM algorithm or performance candidate. No Kernel or CI is created. It requires only existing622d declarations and preserves the same8USize/2array/8Float32 parameter order on both recursive definitions.

Both arrays explicitly use @&. Fixed InferBorrow's source says user borrow annotations override performance ownership heuristics; correctness-forced ownership still wins for reset/reuse or required self-tail handling. These arrays are never reset, mutated or stored into a result; they are read and forwarded to the other explicitly borrowed parameter. This removes the obvious need to decrement an owned input array after a cross-call. It does **not** prove the final emitted C has no post-call RC, and it does not extend Lean's self-only TCO rule to mutual calls.

The Hot toy reads each array's first UInt32 with a total default, uses one bit to select a direct numeric-cast/update or the Cold edge. Cold includes one existing Float32.ofBits import and updates all eight arbitrary incoming Float32 values before handing them back. All eight machine-word parameters participate in control/progression or the Cold conversion, so no intentionally dead placeholder is used to mimic ABI size. The termination measure is2*(count.toNat-k.toNat)+phase, with phase1 forHot and0 forCold; this is proof data, not a runtime Nat/fuel argument. Original Packed10Index.next_decreases supplies the no-wrap progress fact.

Terminal output uses the existing B2 R15ThinPairs.F2, combining all eight values only at completion. B2 does not have the suggested F4 type. Choosing F2 avoids inventing a state datatype and leaves the relevant result ABI as an object pointer; it is **not** evidence about a real BMM terminal layout. No tuple/record is intentionally constructed on a transition, no continuation closure is passed, and no input panel is built.

The first future codegen check must inspect all three exact definitions and both cross-edges. Reject on boxed Float32/state/PSum transition objects, a dynamic apply/closure, an ABI mismatch after reduction, RC or other work after a cross-call, or regular call/return growth instead of two sibling tail jumps. Also inspect Hot's self-backedge and any additional calls from generic array access. No claim about actual jmp, stack growth, q residency, compilation, or speed is made here. A source-level noinline annotation and explicit borrow are conditions to test, not substitutes for that result.

No added extern/unsafe/implemented_by/axiom, no compiler/flag changes, no indexed8 edit, no new confirmation input/result. The existing fixed compiler source record TAIL-CONTINUATION-ABI-PREMISE.md remains the basis for this narrow probe; there is only this one version.
