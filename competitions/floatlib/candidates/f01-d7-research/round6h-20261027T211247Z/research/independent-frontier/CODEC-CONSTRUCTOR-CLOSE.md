# Public Float32 construction does not bypass the fixed codec boundary

Seven fresh primary files at exact Lean293d5d0c,95441B, match their Git blobs in `codec-source-index.json`. The public `Float32` constructor is named `Float32.ofModel`. Fixed `Float32.lean:37–44` declares it and directly assigns **`extern "lean_float32_of_bits"`**. `Float32.ofBits` is separately assigned the very same runtime function at132. Writing `Float32.ofModel model`, record constructor syntax `⟨model⟩`, or an inline Lean wrapper around either therefore does not select a different supported scalar bitcast entry.

This conclusion is grounded in compiler behavior, not just logical equality:

- Fixed `tests/elab/float_compiler.lean:85–101` contains a `#guard_msgs` regression test for `def g : Float32.Model → Float32 | a => ⟨a⟩`. Its asserted Compiler.result retains a `Float32.ofModel` call. We inspected the pinned test source; we did **not** rerun that test.
- LCNF `Util.lean:40–46` lists Float32 as a runtime builtin. `Irrelevant.lean:59,86` excludes builtin types from trivial single-field structure elimination. The nearby ordinary `Foo` compiler test erases its wrapper, while the Float32 constructor test intentionally does not.
- Existing fixed `ToDecl.lean:148–151` gives declarations with extern metadata an `.extern` value before ordinary body conversion. `ToImpure.lean:125–128` uses the available function signature before ordinary constructor layout. `EmitC.lean:642–652` emits a function call for a standard extern entry; inline C patterns are a different metadata case, not supplied by this constructor.
- The fixed header declares `lean_float32_of_bits` at3253 as exported, whereas native add/mul and numerical UInt32 casts have visible static-inline bodies. `object.cpp:1987–1992` implements the exported bit codec with `std::bit_cast` plus NaN canonicalization. The actual competition compile is separate-O3/no-LTO in the inspected capture; a proof does not expose that C++ body to the caller.

**Do not invent a model-allocation penalty.** `Float32.Model` has one UInt32 field and a Prop validity field. That proof and its ordinary wrapper can erase to the word; the pinned constructor test is consistent with this. The blocker is the retained outer scalar codec call, not evidence that every model construction allocates. Executing a generic model unpack/pack might do additional work, but no unmeasured allocation claim is needed here.

**The all-input semantic target also needs care.** `Float32.Model.valid` admits only the canonical NaN representation. A constructor `{toBits:=u,valid:=...}` cannot accept every arbitrary raw NaN payload without normalization. `Float32.Model.ofBits` normalizes through unpack/pack; the native codec likewise canonicalizes NaN. A correct replacement must equal the existing Float32 import, while original Binary32 words remain available for payload-sensitive fallback. A universal `toBits(ofBits(u))=u` is false for arbitrary noncanonical NaNs.
