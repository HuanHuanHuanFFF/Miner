# merge操作

执行规则见[AGENTS.md](../AGENTS.md)。在仓库根目录调用：

```powershell
# 只预检，不联网、不修改Git
python scripts/merge操作.py

# 已获合并、推送、清理授权时执行完整操作
python scripts/merge操作.py --execute --push --cleanup

# 也可明确指定本轮分支
python scripts/merge操作.py codex/round21 --execute --push --cleanup
```

省略分支时处理全部本地及origin tracking记录中的`codex/`实验分支，其他分支在预检中列为排除项。执行模式先刷新远端；同时存在的本地与远端实验分支必须一致。分叉、脏工作区或进行中的Git操作需先单独核对处理。main已有未推送提交会保留。

脚本定位已检出main的工作区，检查项目后合并所选提交，使用带`[skip ci]`的合并说明；合并后重新运行项目检查，按参数推送并核对远端main。随后以精确远端SHA保护删除所选远端分支，本地检查祖先关系后安全删除。执行模式的逐步回执位于共享Git目录下的`merge-receipts/`，失败也保留已经完成的步骤。

冲突或验证失败时停在现场，后续推送和删除不执行。查看工作区与回执，修复并提交后重新调用；脚本不会自动重置、强删或提交未跟踪材料。推送失败时本地合并仍保留，重跑会跳过已合并提交。

所选分支占用的干净工作区会先detach；仓库内且没有忽略文件的多余worktree可移除。有忽略资料、位于仓库外的worktree原样保留并列入回执，由Agent核对后处理。脚本读取Git状态，不读取或归档秘密材料。

脚本完成后Agent仍检查：本轮报告、任务索引、方法文档和看板是否已在研究收尾更新；本地与远端身份、原始证据及回执是否一致。文件命名分类沿用开发阶段规范，仅有实际问题时整理。脚本不生成研究结论，也不刷新竞赛成绩或启动CI。

维护验证：`python scripts/test-merge-operation.py`，使用临时本地仓库和bare远端验证合并、失败停止及清理保护。
